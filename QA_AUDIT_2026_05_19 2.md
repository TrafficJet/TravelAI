## Критические баги (P0) — блокируют использование

### P0-1 — `app/(tabs)/_layout.tsx:129` — Первая вкладка таб-бара показывает иконку "назад" вместо чата

**Описание.** Вкладка `index` (чат-лоадер) настроена с иконкой `arrow-back-outline` / `arrow-back` вместо иконки чата. Пользователь видит стрелку "назад" как первую кнопку таб-навигации.

```tsx
// Текущее состояние — НЕВЕРНО
tabBarIcon: (props) => (
  <TabIcon {...props} icon="arrow-back-outline" iconFocused="arrow-back" />
),
```

**Как чинить.** Заменить на `chatbubble-outline` / `chatbubble` (или убрать вкладку из таб-бара через `href: null`, так как этот экран — лишь редирект на `/chat/:id`).

### P0-2 — `components/chat/BookingConfirmModal.tsx:146-147` — Двойное закрытие модала при успешном бронировании

**Описание.** При успешном `onConfirm()` внутри модала вызывается `onCancel()` (строка 147). При этом в `[sessionId].tsx:644` `onCancel` определён как:
```tsx
onCancel={() => { setPendingBooking(null); setPendingBookingId(null); }}
```
А `handleConfirmBooking` в `[sessionId].tsx:518` сам вызывает `setPendingBooking(null); setPendingBookingId(null)` и затем делает `router.push`. В итоге стейт очищается дважды. Хуже другое: `toast.success` и `sendBookingConfirmation` вызываются в `BookingConfirmModal`, а `router.push('/booking-success')` — в `handleConfirmBooking`. Это два разных потока уведомлений о "успехе" одного и того же события. Пользователь видит toast "Бронирование успешно оплачено!" до того, как роут успел перейти, а затем роут ещё переходит на `/booking-success`.

**Как чинить.** Убрать `onCancel()` и `toast.success(...)` из `BookingConfirmModal.handleConfirm` — весь post-success flow (toast, навигация, нотификация) делегировать вызывающему коду (`handleConfirmBooking` в `[sessionId].tsx`).

## Серьёзные баги (P1) — нужно исправить до релиза

### P1-1 — `app/(tabs)/profile.tsx:661-662, 954-1002` — Состояние `recentBookings` / `isLoadingBookings` и хелперы-функции объявлены, но нигде не используются в JSX

**Как чинить.** Либо убрать мёртвый код и API-вызов, либо восстановить рендеринг раздела "Последние поездки" если он был запланирован для UI.

### P1-2 — `app/(tabs)/profile.tsx:824` — Устаревший API `MediaTypeOptions` expo-image-picker

**Описание.** Код использует `(ImagePicker as any).MediaTypeOptions?.Images ?? 'Images'`. В expo-image-picker v16+ `MediaTypeOptions` удалён, вместо него нужно использовать `{ mediaTypes: ['images'] }` (массив строк). Из-за `as any` TypeScript не поймает ошибку, но на runtime пикер может получить некорректный тип медиа.

**Как чинить.** Заменить на `mediaTypes: ['images']` согласно документации expo-image-picker ^16.x.

---

### P1-3 — `app/chat/[sessionId].tsx` — Нет `useSafeAreaInsets` / `SafeAreaView`

**Описание.** Основной чат-экран не использует safe area insets. На iPhone с Dynamic Island / notch контент может перекрываться статус-баром. При этом соседние экраны (bookings, wallet) корректно используют `useSafeAreaInsets`.

**Как чинить.** Добавить `useSafeAreaInsets` и применить `paddingTop: insets.top` к корневому `View`.

---

### P1-4 — `app/(tabs)/profile.tsx` — Нет `useSafeAreaInsets` / `SafeAreaView`

**Описание.** Экран профиля начинается с `<ScrollView>` без учёта safe area. На устройствах с вырезом/Dynamic Island верхняя часть аватара и имени будет обрезана заголовком.

**Как чинить.** Добавить `useSafeAreaInsets()` и `paddingTop: insets.top` к корневому ScrollView (либо заменить `style.content` padding).

---

### P1-5 — `app/(tabs)/_layout.tsx:152-157` — Экран `profile` не имеет `headerShown: false`

**Описание.** Для `bookings`, `wallet` явно задан `headerShown: false`. Для `profile` этот параметр не задан — заголовок рендерится автоматически через `Tabs`, что создаёт двойной заголовок (от Tabs и от встроенного контента).

**Как чинить.** Добавить `headerShown: false` в options для вкладки `profile`.

---

### P1-6 — `app/onboarding.tsx:269` — `SLIDES[currentIndex]` вызовется с `undefined` при граничном значении `currentIndex`

**Описание.** `SLIDES[currentIndex].gradientEnd` без guard-а. Если `currentIndex` каким-то образом выйдет за пределы массива (сдвиг при быстром свайпе, краш в `onMomentumScrollEnd`), произойдёт `TypeError: Cannot read properties of undefined`.

**Как чинить.** `SLIDES[currentIndex]?.gradientEnd ?? Colors.background`.

---

### P1-7 — `components/chat/ChatHistorySheet.tsx:453-461` — Переименование чатов недоступно на Android

**Описание.** `Alert.prompt` существует только на iOS. На Android показывается заглушка "Переименование через текстовый ввод скоро будет доступно на Android." — кнопка-карандаш нефункциональна на ~50% целевых устройств.

**Как чинить.** Реализовать кастомный Modal с TextInput для Android (или использовать библиотеку типа `react-native-prompt-android`).
